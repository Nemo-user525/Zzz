# 企查查企业搜索接入

## 当前默认线路

消费者主页默认 `QCC_PROVIDER=mcp`，直接连接 `https://agent.qcc.com/mcp/company/stream`，由企查查返回工具字段并进入最终模型判断。个人账号可使用企业工商服务，无需创建 WorkBuddy 第三方应用；权限及额度以企查查账号为准。官方说明见 [企查查智能体平台](https://agent.qcc.com/guide)。

本仓库按账号所有者明确同意公开的要求，在 `configs/qcc-mcp.json` 提供共享演示配置。服务端非空的 `QCC_MCP_URL`、`QCC_MCP_API_KEY` 优先；Bearer 前缀会规范化。删除共享配置并移除环境密钥可停用该凭据。接口和前端只显示状态，不返回密钥；公开仓库的配置文件本身是公开交付，仍可能被其他人使用，配额不是每个检出独立分配。

默认工具为工商登记、财务、工商变更、企业年报；通过实际 `tools/list` 识别参数后只读查询。发现阶段仅请求工商登记，品牌关联同时依赖公开搜索并要求用户确认公司。精确主体确认后，响应的主公司名必须一致，关联企业中的同名字段不能冒充主公司。

原始 JSON 转为有采集时间的字段片段；工商登记最多 3 段、变更最多 6 段、年报最多 6 段、财务最多 4 段，长响应标注截断。每条变更保留事件日期与项目，每份年报保留年度；不把采集日期当事件日期。无记录的响应仅写入查询日志，页面不生成空来源卡片。多个字段片段仍属于同一供应商。

本次实际返回工商登记、变更和年报共 15 段；财务返回无记录，不生成真实收支基线。登记存续和“不公示”都不能证明资金充足。完整模型验收见 [记录](CONSUMER_ACCEPTANCE.md)。

WorkBuddy 仅作为具备应用资格账号的可选方式，显式设置 `QCC_PROVIDER=workbuddy` 后使用；个人账号无需走这条线路。默认 MCP 失败不会切换到 Cookie 网页抓取。

下面保留旧网页/API 适配器文档，仅显式 `QCC_PROVIDER=direct` 使用。原历史研究入口的 API 736 设置独立保留。官方 MCP 配置章节对应当前默认 `mcp` 线路。

## 旧路线：Cookie 网页会话

后端默认读取随仓库分发的 `configs/qcc-web-session.json`。该文件包含账号所有者明确授权公开的会话；新检出无须先填写 Cookie。非空的环境变量／本机 `.env` 中的 `QCC_WEB_COOKIE` 优先于该文件，网页弹窗配置优先于两者。弹窗清除会话在当前进程中生效；重启恢复文件配置。要持续停用，删除该文件并移除本机 Cookie 环境配置。文件缺失或格式无效时继续其他渠道，不阻止启动。会话仍需联网，过期或网站校验失败后需重新登录。

更新会话：

1. 在本机消费者首页的弹窗点击“打开企查查并登录”，本人完成登录、验证并打开公司页。
2. F12 → Network，刷新公司页，选择该公司 HTML 请求，在 Request Headers 复制 Cookie 的值，不带 `Cookie:` 前缀。
3. 粘贴到本机弹窗，点击“配置本次会话”，再重新查询。弹窗输入只驻留服务端内存；需要本机持久覆盖时设置 `.env` 的 `QCC_WEB_COOKIE` 并重启。
4. `GET /api/consumer/qcc-session` 只返回状态；`POST` 配置/清除只允许本机 Host、来源和直连客户端。公网隧道和转发请求禁止配置。前端输入框遮蔽并在配置后清空，不使用 localStorage。

后端仅向搜索结果真实披露的 HTTPS `www.qcc.com/firm/<32位ID>.html` 或 `www.qcc.com/firm_<32位ID>.html` 发送本人 Cookie，不发送到其他域或未知 API，不跟随携带凭据的重定向。401、明确登录跳转或登录提示触发登录状态；403 单列访问拒绝，不擅自断言会话失效；405/429、访问超频和验证码记为限制访问，不自动破解或重试。HTTP 200 的编码验证内容也会标记为 `verification_required`，本机界面提示前往官网验证，不计入已读取正文。只有返回内容包含目标公司（标题可识别时）及工商字段标记，才可作为正文；空壳、导航或其他公司页面会排除。网页成功读取仍是来源材料，不升级为官方核验。网站只返回动态壳时，保留摘要与状态，不能声称取得隐藏工商字段。

2026-10-02 本机对实际公司页的普通访问出现“访问超频”。用户随后提供本人 Cookie，保存到本机 `.env`，并进一步明确授权随仓库公开分发。真实读取出现过拒绝响应和 HTTP 200 无可用正文，尚未取得工商正文，不能把配置或状态码当成接通证明。F12 复制的是本人会话，不能替代付费权限，也不会得到官方 API Key。

如果有权查看的工商资料在 JSON 网络响应中，可导出包含响应体的 HAR，在本机运行：

```powershell
.\.venv\Scripts\python.exe .\import-qcc-har.py --file C:\path\qcc.har --company 公司全称
```

导入器只接受 `qcc.com` 及其子域的成功 JSON 响应，精确匹配企业名，提取登记状态、成立日期、注册资本、登记机关、法定代表人、经营范围。请求头、Cookie、Token、联系方式及 URL 参数均不复制；原始 HAR 不保存到项目，企业字段写入忽略的 `data/raw/qcc-web-evidence.json`。记录标注历史导入、未在线复验，不能视为官方接口证据。它是动态网页的人工补充入口，不是自动抓取私有 API。

## 消费者主页：官方 MCP（新增）

仅在 `QCC_PROVIDER=direct` 时，`/` 消费者调查优先使用已配置的官方 MCP，否则沿用 API 736。两种方式都需要本人合法账号的权限与额度。协议与引用校验经自动测试验证，不能据此称实际企查查账号已联调。

1. 在 [企查查智能体平台](https://agent.qcc.com/guide)注册/登录，获取官方 Streamable HTTP 接入 URL 和 Bearer API Key。平台公布有开发者体验及每日赠送额度，具体以账号页面为准。
2. 在项目 `.env` 设置 `QCC_MCP_URL`、`QCC_MCP_API_KEY`。URL 必须是官方 `qcc.com` 子域的 HTTPS 地址，密钥放在服务端请求头，不写入前端。
3. `QCC_MCP_TOOLS` 是工具名称到企业关键词参数名称的 JSON 映射，默认工商登记、财务、变更、年报四个工具均为 `auto`。`auto` 根据实际 `tools/list` 的 schema 识别 keyword、searchKey、companyName 等常用字符串参数；本次真实服务器要求 `searchKey`，不要沿用旧的 keyword 映射。不同服务器若使用其他名称，可显式配置参数。每次最多调用 5 个显式配置的只读 get/query/search 工具。
4. 后端执行 initialize → tools/list → schema 检查 → tools/call。配置有误、额度不足、返回主体不同或仅有无法解析的文本时，不生成企业记录；页面只显示成功取得的材料，失败状态保留在折叠的调查记录中。

来源链接是官方接入文档，接口原始字段有明确标识，不冒充国家公示原件。模型不能自行构造 MCP 工具名、读取密钥或更换服务地址。API 736 与 MCP 配置不能代替真实联调验收。

## 保留的历史研究入口与 API 736

入口：现有「企业检索与历史回放」页面顶部的统一搜索栏，或打开 `http://127.0.0.1:5173/?view=history`。旧的 `?view=company` 链接也进入该页面，不再提供独立企业查询页面。

流程：输入企业名称或证券代码 → 点击查询 → 选择已入库企业，在当前页面查看历史资料；公开公告并行查询，可先查看本地结果。企查查启用后，同一搜索同时补充企业工商资料，确认返回的企业身份后按需展开处罚、执行、纳税、抵押、质押与变更记录。统一社会信用代码匹配需启用企查查。输入变化立即隐藏旧资料；打字、页面加载和确认身份不调用收费查询。

缺少企查查密钥不禁用搜索。此时仍调用 `/api/v2/companies?query=...` 与 `/api/v2/discovery?query=...`，明确提示工商与信用资料尚未启用。公开来源失败或超时也不影响选择已入库企业，并提供官方核验入口。

## 配置

开通[企查查企业风险扫描接口 736](https://openapi.qcc.com/dataApi/736)所需权限。在项目根目录 `.env` 中配置 `QCC_APP_KEY` 与 `QCC_SECRET_KEY`，或者在启动后端的环境变量中配置。真实密钥只保存在本机，不能放入前端、截图或提交 Git。已有 `.env` 时仅追加两项，不覆盖其他设置。

`start.ps1` 与 `start.sh` 会在 `.env` 存在时通过 uvicorn `--env-file .env` 加载；配置后重新启动后端。手动启动时同样需要传 `--env-file .env` 或设置环境变量。状态接口只表明密钥已配置，不代表权限与额度已通过在线验证。

## 接口

- `GET /api/integrations/qcc/status`：仅返回配置状态，不调用企查查、不返回密钥。
- `POST /api/integrations/qcc/lookup`：请求 JSON `{"query":"企业全称或统一社会信用代码"}`。后端调用固定的 `https://api.qichacha.com/ECIInfoOverview/GetInfo`，Token 使用 `MD5(AppKey + Timespan + SecretKey).upper()`。本接口是单企业查询，不能当作模糊候选列表接口。
- 输出：企业身份、按类别整理的记录、查询时间、来源和覆盖限制。空列表与缺失字段分别显示。金额保留接口原值及单位，不擅自换算。
- 未配置返回 503，超时返回 504，空企业结果返回 404，供应商拒绝/错误响应返回 502；不返回供应商原始错误正文、密钥或带密钥的请求 URL。不自动重试。

## 边界与验证

这是当前资料查询，结果不写入历史回放库、不自动变成已核验事实、不替换现金模型中的企业。确认企业后仅解锁资料展示。现金计划、客户集中度、关键员工依赖需要另外补充。

部分字段接口最多返回前 100 条，因此页面显示的是「本次返回条数」。缺失、空列表和查询失败都不能表述成无风险。工商变更不自动等同于股权变更，注册资本不等同于可用现金。

本地自动测试使用模拟供应商响应，覆盖签名、缺少密钥、查询校验、响应规范化、错误脱敏、过期响应忽略与确认后展开。真实接口联调需管理员配置有效凭证及接口权限后进行。

公网演示通过 `app.public_demo:app` 提供 `frontend/dist` 静态资源。前端修改后需重新构建再刷新页面；后端修改需重启后端进程。Cloudflare 临时隧道进程保持运行时沿用原链接。当前演示未配置企查查凭证；若开放收费查询，应为该入口配置认证与调用额度控制。
