# 企查查企业搜索接入

入口：现有「企业检索与历史回放」页面顶部的统一搜索栏，或打开 `http://127.0.0.1:5173/?view=history`。旧的 `?view=company` 链接也进入该页面，不再提供独立企业查询页面。

流程：输入企业名称或证券代码 → 点击查询 → 选择已入库企业，在当前页面查看历史资料；公开公告并行查询，可先查看本地结果。企查查启用后，同一搜索同时补充企业工商资料，确认返回的企业身份后按需展开处罚、执行、纳税、抵押、质押与变更记录。统一社会信用代码匹配需启用企查查。输入变化立即隐藏旧资料；打字、页面加载和确认身份不调用收费查询。

缺少企查查密钥不禁用搜索。此时仍调用 `/api/v2/companies?query=...` 与 `/api/v2/discovery?query=...`，明确提示工商与信用资料尚未启用。公开来源失败或超时也不影响选择已入库企业，并提供官方核验入口。

## 配置

开通[企查查企业风险扫描接口 736](https://openapi.qcc.com/dataApi/736)所需权限。在项目根目录 `.env` 中配置 `QCC_APP_KEY` 与 `QCC_SECRET_KEY`，或者在启动后端的环境变量中配置。真实密钥只保存在本机，不能放入前端、截图或提交 Git。已有 `.env` 时仅追加两项，不覆盖其他设置。

`start.ps1` 与 `start.sh` 会在 `.env` 存在时通过 uvicorn `--env-file .env` 加载；配置后重新启动后端。手动启动时同样需要传 `--env-file .env` 或设置环境变量。状态接口只表明密钥已配置，不代表权限与额度已通过在线验证。

## 接口

- `GET /api/integrations/qcc/status`：仅返回配置状态，不调用企查查、不返回密钥。
- `POST /api/integrations/qcc/lookup`：请求 JSON `{"query":"企业全称或统一社会信用代码"}`。后端调用固定的 `https://api.qichacha.com/ECIInfoOverview/GetInfo`，Token 使用 `MD5(AppKey + Timespan + SecretKey).upper()`。本接口是单企业查询，不能当作模糊候选列表接口。
- 输出：企业身份、按类别整理的记录、查询时间、来源和覆盖限制。空列表与缺失字段分别显示。金额保留接口原值及单位，不擅自换算。
- 未配置返回 503，超时返回 504，空企业结果返回 404，供应商拒绝/错误响应返回 502；不返回供应商原始错误正文、密钥或带密钥的请求 URL。不自动重试。

## 边界与验证

这是当前资料查询，结果不写入历史回放库、不自动变成已核验事实、不替换现金模型中的企业。确认企业后仅解锁资料展示。现金计划、客户集中度、关键员工依赖需要另外补充。

部分字段接口最多返回前 100 条，因此页面显示的是「本次返回条数」。缺失、空列表和查询失败都不能表述成无风险。工商变更不自动等同于股权变更，注册资本不等同于可用现金。

本地自动测试使用模拟供应商响应，覆盖签名、缺少密钥、查询校验、响应规范化、错误脱敏、过期响应忽略与确认后展开。真实接口联调需管理员配置有效凭证及接口权限后进行。

公网演示通过 `app.public_demo:app` 提供 `frontend/dist` 静态资源。前端修改后需重新构建再刷新页面；后端修改需重启后端进程。Cloudflare 临时隧道进程保持运行时沿用原链接。当前演示未配置企查查凭证；若开放收费查询，应为该入口配置认证与调用额度控制。
