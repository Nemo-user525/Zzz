# 门店查证与对话

默认页面 `/` 把“找地点 → 核对企业 → 阅读接口返回 → 继续提问”放在同一条路径上。消费者模型调查、历史证据和交易现金流分别在 `/?view=consumer`、`/?view=history`、`/?view=trade`。这些入口共享 FastAPI 服务，但数据来源与结论口径不同。

## 数据流与边界

1. `GET /api/regions`、`GET /api/places` 使用高德 Web 服务查行政区与地点。省、市、区县可选；区县以 `adcode` 限定搜索。街道没有独立 `adcode`，会检查最多 3 页地点候选，并按名称、地址筛选，最多展示 20 条。选中后 `GET /api/place-map` 通过服务端获取静态地图预览，并提供高德 URI 链接打开交互地图；地点仅是门店线索，筛选无结果不能证明当地没有门店。
2. `GET /api/legal-entities` 优先使用已有企查查智能体 MCP 的 `get_company_by_query` 返回企业候选；门店全名无匹配时，依次尝试去掉括号中的分店名和常见门店后缀，并明确提示扩大了关键词。用户需自行核对营业执照、合同抬头和收款方。
3. `POST /api/company-report` 对用户选定的准确企业名称或信用代码，使用企查查智能体 MCP 查询工商登记、企业资料和 35 项风险因子扫描；只对扫描中有记录的因子再调用对应明细工具。报告首页给出较低／中等／较高三级风险判断和付款建议，判断依据在卡片中直接列出。页面保留本次返回的原始字段、查询时间、每项成功或失败状态。扫描命中数与明细返回数可能不同；缺失和失败不证明没有风险。没有 MCP Key 且另有开放平台凭据时，才使用 886/736 兼容线路。
4. `POST /api/chat` 接收最多 500 字的问题及本次会话的企业名称。FastAPI 将 Node 服务的 SSE 事件转发给浏览器；`context` 标识本轮企业，`delta` 是回答片段，`done` 结束。浏览器传入企业上下文，服务端不跨访客共享“上家公司”。
5. Node 对话服务优先查询企查查官方 MCP，再调用 OpenAI 兼容模型。缺少凭据或上游失败时可能使用有限的内置兜底资料；回答与报告均需结合原始公示核对，不能据此作投资保证。

`POST /api/investigations` 是独立的公开网页线索预览：返回候选、覆盖情况和失败状态，主体默认未确认。它不替代消费者调查页的模型分析。

## 首页风险等级

首页报告对**用户选择的企业**做预付消费建议，不把地图 POI 自动当作这家企业经营的门店。页面先展示等级、触发依据和建议，再提供工商字段、35 项风险扫描与命中项原始明细；报告对象和资料范围放在可展开说明中。付款前的行动提示是确认合同与收款方名称。

分级规则在 `backend/app/services/qcc_discovery_risk.py`，版本为 `qcc-company-records-v1`：登记为吊销、注销等停止状态，或失信、限高、破产重整、严重违法有扫描命中且明细返回记录，判为较高；执行、经营异常、行政处罚等关注项，或近三年企业作为被告的服务相关裁判文书，判为中等。登记正常、扫描至少覆盖 30 类、没有上述触发记录且明细无失败时，才判为较低。覆盖不足、明细失败时按中等的谨慎档展示。司法记录总数不会单独触发较高等级；同一案件的原告、被告角色分开识别。这个规则是产品的消费决策分级，**不是企查查或监管部门发布的官方评级**。监管部门对健身预付消费的合同、收款主体与退款信息也提出了明确提示，参见[广州市市场监管局的消费提示](https://scjgj.gz.gov.cn/zwgk/rdhy/content/post_10464869.html)及[南京市体育局的管理通知](https://sports.nanjing.gov.cn/njstyj/202401/t20240109_4141247.html)。

## 文件与配置

| 部分 | 位置 |
|---|---|
| 首页与对话界面 | `frontend/src/ProductApp.tsx`、`DiscoveryFlow.tsx`、`ChatSection.tsx` |

| 对话代理 | `backend/app/api/chat.py` |
| 对话逻辑与官方 MCP | `chat/server/index.mjs`、`llm.js`、`qcc-mcp.js`、`company-data.js`、`prompt.js` |

根目录 `.env.example` 列出 `AMAP_WEB_SERVICE_KEY`、可选的 `QCC_APP_KEY`、`QCC_SECRET_KEY` 和 `CHAT_*` 覆盖项；共享 MCP Key 位于 `configs/qcc-mcp.json`，也可由服务端 `QCC_MCP_API_KEY` 覆盖。演示凭据已按账号所有者授权提交；公开仓库访问者可读取和使用，额度由同一账号承担。`start.ps1 -Demo` 启动单端口页面与本机对话进程；开发模式使用 `start.ps1` 或 `start.sh`。`GET /api/integrations` 和 `/api/chat-health` 只返回配置状态，不返回凭据。

## 已知限制

- 高德地点与企查查企业记录没有自动证实的经营关系。
- 2026-10-03 已用共享演示 Key 真实调用高德地点搜索及企查查智能体候选、工商登记、风险扫描和命中项明细。乐刻之江饭店店的高德地点可定位，但“乐刻私教馆(之江饭店店)”全名没有匹配企业；扩大到“乐刻私教馆”返回杭州乐刻网络技术有限公司这一候选，尚不能证明它是该门店的经营主体。
- 企查查智能体扫描和明细是两个工具：35 项风险因子扫描给出命中数，命中项再查明细。页面不会把扫描数写成实际明细数，也不会把这一流程称为开放平台 736 响应。供应商可能限制明细窗口。
- 新克隆从 `.env.example` 获得高德共享演示配置，已有 `.env` 需自行补入。企查查 886/736 的独立凭据仍未配置，该兼容线路只通过模拟接口测试。
- 企查查 886/736、官方 MCP 是不同接口与额度；一条路线成功不代表另一条可用。
- 内置兜底只含少数主体且有固定资料日期，不等同于实时查询；公司同名、简称和境外主体需要格外核对。
- GitHub 提供代码与公开演示配置，不承载在线服务。公网访问须另行部署并确认上游额度、流式代理与并发能力。
