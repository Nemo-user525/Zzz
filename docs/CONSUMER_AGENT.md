# 真实消费者调查与 LangGraph 智能体

本次演示直接检索用户输入，不使用虚构门店或数据库样本替代搜索结果。默认页面 `/`；原企业研究与历史回放 `/?view=history`；原现金流演示 `/?view=trade`。

## 实际流程

1. 输入门店、品牌或公司及可选位置，执行公开搜索、网页读取和已配置的企查查 API 736。
2. 列出有来源支撑的公司名，由用户确认研究对象。不会自动把品牌总部视为门店经营者。无可靠候选时显示缺口，仍可阅读关键词资料。
3. 真正运行 `langgraph.graph.StateGraph`：`collect → plan → tools → plan → synthesize`。基础检索包括经营变化、服务持续、退款履约、回应、官方记录、新闻及小红书公开索引。数据库匹配命中时追加对应复核查询；无匹配时仍执行独立调查。
4. 配置在线模型后，模型根据新取得资料和数据库主题参考，选择额外检索词及来源 ID，最多两轮。服务端给每个检索词加当前主体名，只允许读取已取得的公开来源。
5. 模型生成结构化证据解释、逐字引文和具体核实问题。Pydantic 校验格式；来源必须属于本次、提及所选主体且引文位于摘录中。校验失败明确回退。引用校验不等于事实或解释真实性核验，因此界面明确标记“AI 解释，待核实”。
6. 原始品牌/门店的新闻与小红书索引另行查询，只有品牌提及时放入 `brand_context`。它们不计入所选公司指标，模型不得把它们引用为该公司的证据。

展示的是实际工具动作和证据摘要，不要求或展示模型内部思维链。

## 六项大众指标

| 指标 | 展示内容 | 不能据此声称 |
|---|---|---|
| 门店与公司是否对应 | 选定主体、名称依据、门店归属缺口 | 用户选择等于工商核验 |
| 服务能否持续 | 营业、停业、搬迁、承接等相关材料 | 关键词出现即确定会停业 |
| 退款与履约线索 | 退款、课包、储值和权益材料及核实问题 | 投诉均属实或代表整体情况 |
| 经营主体有何变化 | 有内容支持的变更、处罚等线索 | 目录标签等于真实处罚；子公司等于母公司 |
| 回应与后续处理 | 是否执行补查、有无回应材料 | 找到回应就推翻另一事件 |
| 判断依据够不够 | 所选公司相关来源、站点、正文及接口条数 | 来源多即可信；没有记录即安全 |

不计算安全分、跑路率或消费者损失概率。缺少两个有来源的时间点时不输出恶化趋势。输入金额不进入企业判断，前端只显示本次拟消费金额。

## 数据库的作用与现状

`consumer_criteria.py` 从历史库 `source_supported` 断言中，排除后续结果样本，校验 PDF SHA256、页码及逐字摘录，再训练字符双字组最近质心主题模型。主题匹配与版本化复核准则相连，建议查处罚后续、区分上市状态和营业状态、核对子公司范围等。准则文字是人工编写的约束，主题路由才是样本训练结果；不称它为已验证的风险预测模型。

本机本轮训练：**5 条主题样本，0 条具名人工复核**。未做独立验证，不报告准确率。样本主要来自上市公司，尚不足以验证健身预付风险预测；当前企业资料与训练企业实例严格分开。历史样本不作为当前公司证据，不作为 demo 返回值。

模型文件 `data/models/consumer-topic-router.json` 和查询缓存不进入 Git。启动脚本执行 `app.prepare`，读取根目录 `.env`、幂等导入原数据并重新训练主题参考。新克隆需要先按 `INGEST_RUNBOOK.md` 恢复研究数据库；缺样本时明确显示不足，仍允许真实查询。

## 运行与配置

安装 `backend/requirements.txt`，其中固定 `langgraph==1.2.12`。现有 `LLM_PROVIDER / LLM_BASE_URL / LLM_MODEL / LLM_API_KEY` 继续使用，无需新增模型厂商。复制 `.env.example` 为根目录 `.env`，密钥只存服务端。`start.ps1`、`start.sh` 会传入 `.env`。

```powershell
pwsh -File .\start.ps1
```

可选 `TAVILY_API_KEY` 启用 Tavily API；未配置时使用 360 公开网页适配器，页面变更、限制或网络失败会明确显示。`QCC_APP_KEY / QCC_SECRET_KEY` 还需要 API 736 权限及额度。小红书目前只有公开网页索引，**没有官方平台 API、登录后笔记或全量内容**。

无模型密钥时 LangGraph 仍执行真实工具流程，但报告明确标为“实时检索 + 规则指标”，不能当作完整在线智能体的验收成功。配置存在也不代表调用成功，以报告工具记录为准。

可重复的真实网络验收（不在普通自动测试中联网）：

```powershell
$env:PYTHONPATH = 'backend'
.\.venv\Scripts\python.exe -m app.consumer_smoke --query 乐刻
# 先核对上一步候选，再指定要研究的完整公司名：
.\.venv\Scripts\python.exe -m app.consumer_smoke --query 乐刻 --company 杭州乐刻网络技术有限公司 --require-model
```

`--require-model` 只有在线模型实际调用成功、未回退且生成带引用解释时才退出 0。缺少模型会退出 3，不会把规则输出冒充 AI 成功。真实响应保存至忽略的 `data/raw/consumer-live-check.json`。若查询主体不存在返回 2，查询失败或没有真实资料返回 1。

## API 与文件

- `GET /api/consumer/capabilities`：配置状态和训练样本概况，无密钥值。
- `POST /api/consumer/discovery`：`query`、可选 `location`；返回候选、来源、搜索状态。
- `POST /api/consumer/analyses`：本次 `investigation_id`、`candidate_id` 及消费条件；返回六项指标、来源、解释、数据库参考与调查记录。
- 查询缓存独立表，最多 100 条、有效期 24 小时。搜索全部失败时才可显式展示历史缓存；不写入已核验企业事实。
- 调查最多同时 3 个，单请求最长 180 秒。前端可取消并忽略旧响应；切换关键词、主体或消费条件即清除旧分析。
- `services/consumer_agent.py` 是开源运行时与工具循环；`consumer_model.py` 是兼容模型传输；`consumer_registry.py` 复用企查查适配器；`consumer_indicators.py` 维护指标规则。
- `frontend/src/ConsumerWorkspace.tsx`、`api/consumer.ts`、`consumer.css` 为独立消费者视图，不调用现金流接口。
- `docs/openapi-consumer.json` 为当前运行时导出的完整契约。

## 选型依据

采用 [LangGraph](https://github.com/langchain-ai/langgraph)（MIT），因为它允许在同一个状态图里组合可审计规则与模型决定的工具循环，并能在无模型时保留实际工具结果。参见 [官方概述](https://docs.langchain.com/oss/python/langgraph/overview) 和 [Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)。这属于本项目适配选择，不宣称存在一个对所有任务“最好的”开源智能体。

## 本轮验证

实际网络查询“乐刻”，识别北京和杭州两个公司候选；选择杭州主体后读取官网、企业信息页、投诉与报道等真实来源。修复了成立日期被误识别为公司名、企业资料页导航栏目被误当变化线索的问题。网络结果随时间和检索提供方变化，不把固定条数写入程序。

在线模型、企查查授权 API 与 Tavily 的真实账号联调仍待有效配置；本次没有使用测试密钥替代实际账号。自动测试中的受控响应仅存在于测试文件。
