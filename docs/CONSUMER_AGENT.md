# 消费者真实调查实现

运行与配置以根目录 [README](../README.md) 为准。当前默认页面先显示风险初判，全部来源在下方；空来源分类、无资料的指标不渲染。调查失败和评级不足仍显示明确状态。

## 数据流

`discovery → 用户确认公司 → collect → plan → tools → plan → synthesize`

实际使用 `langgraph.graph.StateGraph`（固定 1.2.12）。数据库不是演示数据源：`consumer_criteria.py` 校验历史 PDF 哈希、页码和逐字引用，用 source_supported 断言训练字符双字组主题路由。人工编写的主题复核准则随匹配主题传入模型，并触发最多两类补查。没有匹配也照常独立检索。

基础调查为 24 个方向（含用户口碑与经营收支），360 公开搜索查询两页，同时查询 Bing 国内站公开 RSS 和搜狗公开网页。配置后叠加 Tavily 和博查 API。保留最多 120 条公司资料，再合入品牌/门店材料，总计最多 160 条；同一网站最多 20 条，URL 去除追踪参数后去重。接口记录可能共享说明链接，因此按记录 ID 去重。基础读取 16 份原网页；模型最多两轮，每轮最多两次补查和两份正文读取。检索预算不是覆盖保证，重复转载也不自动成为独立事实支持。

本地 Qwen3.5-9B 的最终风险综合通过真实的 `think=true` Ollama 调用完成；工具规划与资料提取使用直接结构化输出，将推理预算集中在综合判断。免费云端模式使用 OpenRouter 的 Qwen3.8-27B `:free`，每次先查询目录核验价格；无密钥、限流或模型下线不切付费模型。保留显式配置的旧 `LLM_*` 兼容接口。模型内部思维链不展示、不记录；页面展示工具动作、引用和简短理由。

全部保留的公司及品牌资料分批送入模型（本地 6 条，云端 12 条）。调用时使用临时短编号和连续原文片段；模型选择单一 citation_id，评价输出按来源键强制完整覆盖；最终汇总保留各段原文而不拼接。模型选择原文片段编号，由服务器填回原文，避免自行抄写或拼接。每条社区及网页评价材料必须有审阅记录；近似转载单列、不重复计数。引用或覆盖不合格会修正一次，仍无依据的解释整项剔除；评价缺项不能称完整评估。最终综合输入包含全部评价统计、按倾向及主体分组的引用样本、各指标解释与收支情景，控制 16K 上下文负担。完整逐条记录保留在响应和页面。品牌材料只能作为归属未明的背景，不能作为公司不利事实。模型无可用输出时保留已完成的阅读记录，企业证据评级保持未知、模型状态明确标记失败；页面另给出“中等决策风险＋低确信度”的谨慎预付建议，标明 information_gap 规则，不冒充模型结论。

收支基线只接受有原文或授权接口支持的同期间经营现金流入/流出总额，校验金额、单位、日期与主体；营业收入、利润、融资不能替代现金收付款。缺基线时使用指数敏感性试算。情景计算和确信度证据门槛见 [方法说明](CONSUMER_RISK_METHOD.md)。

## 评级与校验

- low：具体正向依据充分，至少 3 个网站、2 种渠道、2 份正文或接口支持，且未出现尚待核实的停业、退款等显著不利线索。并非未来安全承诺。
- medium：存在有来源的不利线索，需要核实范围、时间和后续。
- high：至少两个网站的不利材料，且有正文或接口支持。页面始终标明 AI 初判、公司范围和门店关联限制。
- undetermined：模型未完成、引用失败、材料不足、联网补查全部失败等。

这些是保守展示门槛，不是统计校准模型；原文存在也不等于事件真实。未来需补充消费行业的人工标注与独立验证。不能把数据库主题相似度、投诉数量或缺失资料直接转成风险分数。

企业证据评级在 `risk.level`；始终明确的预付建议在 `decision_level`、`decision_label`、`decision_basis`。依据不足时的中等决策风险来自公开的谨慎规则，不是给公司补造负面事实。

## API

- `GET/POST /api/consumer/qcc-session`：查询状态／本机配置 Cookie。默认加载仓库会话文件，本机非空环境配置可覆盖；网页弹窗覆盖仅驻留内存。
- `GET /api/consumer/capabilities`：配置状态、模型名、训练概况，无密钥。
- `POST /api/consumer/discovery`：关键词、可选位置，返回真实候选和来源。
- `POST /api/consumer/jobs`：提交 investigation_id、candidate_id 和消费条件，202 返回随机 job_id。
- `GET /api/consumer/jobs/{job_id}`：running/completed/failed/cancelled，进度摘要和完整结果。
- `DELETE /api/consumer/jobs/{job_id}`：取消实际后端任务。
- `POST /api/consumer/analyses`：保留同步接口供脚本兼容。

每进程最多 3 个运行任务；最多 30 条任务记录，1 小时过期；调查上限 30 分钟。当前适用于单进程本机演示，不支持跨 worker 共享任务。模型调用串行，避免本机显存被并发任务挤占。浏览器取消、改关键词或条件时终止旧任务，并忽略晚到响应。查询缓存单独存储，不写入已核验事实表。
