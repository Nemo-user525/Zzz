本次用户明确修正旧提示词：最终 demo 必须是真实联网，数据库用于学习判断参考，必须与开源智能体的独立调查互补，并要求推送 GitHub。旧提示词中的虚构健身交互样例和“不推送”条款不再适用。本轮没有添加虚构门店。

## 默认体验

原默认用户是提供账期的制造企业，输入订单及现金条件，输出现金底线推演。现在默认服务准备首次办卡、买大额课包、追加充值或续费的消费者：输入门店/品牌/公司 → 确认候选主体 → 独立联网调查 → 阅读六项证据指标、变化解释、回应和待核实问题。金额与服务时长可留空。

消费者判断关注未来服务履行，不能复用供应商现金流公式。因此消费者视图独立，不依赖 `/api/demo-scenario`、`/api/simulations`、`/api/compare-scenarios`。原两个角色 ID 和原数学含义保留在 `/?view=trade`；企业研究、公开财报与历史回放保留在 `/?view=history`。

## 真实性和未完成事项

网页搜索摘要只是线索；正文取得不等于事实真实；企查查返回不等于原始公示复核；用户选择不等于门店归属核验。品牌资料与所选企业证据分开。全部失败会明确失败或历史缓存，绝不自动换成样例。

本机有 5 条可训练主题样本，0 条具名人工复核。数据库主题匹配连接复核规则，命中时触发补查；在线智能体进一步选择工具、解释证据和反向可能。两者都不提供未经验证的风险概率。仍需扩充真实消费领域样本、独立评估、核实门店关系，才能验证行业专门判断能力。

尚无有效在线模型、企查查及 Tavily 配置，本轮不能宣称三者真实账号调用已验收。小红书仅公开索引，无平台 API。普通回归通过受控模型与网络响应测试循环及校验；真实搜索另行执行。详见 [运行和严格验收命令](CONSUMER_AGENT.md)。

## 商业假设

直接用户为准备长期预付消费的人。优先验证的付费方是经营健身预付产品的本地生活平台，拟把经营主体变化关联到平台具体服务，形成需复核或要求商家说明的事项；可探索按监测商户数或服务订阅收费。以上均待验证，没有已签合作、定价承诺或损失降低数据。
